Integraciones

¿Quién lo puede usar?

Tres perfiles, cada uno con su propia API key y reglas de acceso.

🔑

Autenticación por header

Toda request lleva X-API-Key. La clave determina el scope automáticamente — sin login, sin JWT.

🔍

Búsqueda fuzzy incluida

GET /search con cualquier texto. RapidFuzz rankea por relevancia. Filtrá por tipo, área, estado.

🤖

Contexto para LLMs

POST /ai/context devuelve las notas más relevantes para un query. Ideal para RAG — solo llegan notas con ia_permiso: allow.

📤

Escritura al vault

Con scope personal, creás notas y borradores directamente en el vault desde tu app.

JavaScript — fetch
// Helper base const API = 'https://api.pachimind.app' const KEY = 'tu-api-key' const pm = (path, opts = {}) => fetch(`${API}${path}`, { ...opts, headers: { 'X-API-Key': KEY, 'Content-Type': 'application/json', ...opts.headers } }).then(r => r.json()) // Proyectos activos const proyectos = await pm('/projects/active?area=Laboral') // Búsqueda fuzzy const hits = await pm('/search?q=acme&tipo=proyecto') // Contexto para IA const ctx = await pm('/ai/context', { method: 'POST', body: JSON.stringify({ query: 'proyectos activos Q2', filters: { area: 'Laboral' }, max_results: 5 }) })
📁

Estructura de carpetas

La carpeta donde guardás una nota determina qué tipo es. El frontmatter agrega metadatos: tipo, área, sensibilidad, permisos de IA.

🔒

Control de privacidad por nota

Cada nota decide su visibilidad con sensibilidad e ia_permiso. secreto = nunca visible externamente.

🔗

Wikilinks resueltos

Los [[wikilinks]] se resuelven a IDs de la API automáticamente en GET /notes/{id}.

⚡

Hot-reload

Guardás en Obsidian — la API actualiza el índice en tiempo real. Sin reiniciar el servidor.

YAML — frontmatter de una nota
--- tipo: proyecto # proyecto | accion | decision | persona # cliente | reunion | registro | idea | nota estado: activo # activo | en_proceso | borrador | archivado area: Laboral # Personal | Laboral | Familia | Amigos | Apostolado sensibilidad: normal # normal → visible para todos los scopes # interno → solo personal # privado → solo personal # secreto → nunca visible por API ia_permiso: allow # allow → /ai/context puede incluirla # summary_only → solo excerpt (scope personal) # deny → excluida de /ai/context ia_indexar: true revisado: false cliente: Acme Corp prioridad: alta tags: - estrategia - q2 ---
🌐

Scope public

Solo notas con sensibilidad: normal. Para mostrar contenido en sitios web o widgets sin exponer nada interno.

🤖

Scope ai_context

Para agentes IA. Solo notas con ia_permiso: allow + ia_indexar: true. Nunca recibe contenido completo — solo excerpts de 400 chars.

📋

Sin contenido completo

Los scopes externos nunca reciben el markdown completo. Solo excerpt de texto plano. La privacidad se garantiza en el servidor.

📥

ai_context puede escribir

El scope ai_context puede depositar borradores en el inbox vía POST /inbox/draft para revisión manual.

curl — integración externa
# Scope public: listar proyectos curl https://api.pachimind.app/projects/active \ -H "X-API-Key: clave-publica" # Scope ai_context: contexto para tu LLM curl -X POST https://api.pachimind.app/ai/context \ -H "X-API-Key: clave-ia" \ -H "Content-Type: application/json" \ -d '{ "query": "decisiones recientes sobre arquitectura", "max_results": 5 }' # ai_context deposita un borrador al inbox curl -X POST https://api.pachimind.app/inbox/draft \ -H "X-API-Key: clave-ia" \ -H "Content-Type: application/json" \ -d '{ "title": "Insight generado por IA", "content": "...", "area": "Laboral" }' # Respuesta siempre: # "content": null ← nunca contenido completo # "excerpt": "primeros 400 chars..."
Control de acceso

Tres scopes. Una API key.

El valor de X-API-Key determina automáticamente qué puede ver y hacer cada cliente.

personal
Acceso completo
Para el propietario del vault. Ve todo excepto notas marcadas como secreto. Puede leer y escribir.
  • ✓ Contenido markdown completo
  • ✓ Crear notas (POST /notes)
  • ✓ Crear borradores (POST /inbox/draft)
  • ✓ Sensibilidad: normal, interno, privado
  • ✗ Sensibilidad: secreto (siempre bloqueado)
ai_context
Para agentes IA
Para LLMs y agentes. Solo notas explícitamente habilitadas para IA. Nunca recibe contenido completo.
  • ~ Solo excerpt (400 chars)
  • ✓ Puede depositar borradores al inbox
  • ✓ Solo notas con ia_permiso: allow
  • ✓ Solo notas con ia_indexar: true
  • ✗ Sensibilidad: privado, sensible, secreto
public
Solo lectura pública
Para sitios web e integraciones externas. Solo notas sin ninguna marca de sensibilidad especial.
  • ~ Solo excerpt (400 chars)
  • ✗ No puede crear nada
  • ✗ Sin acceso a /ai/context
  • ✓ Solo sensibilidad: normal
  • ✗ Interno, privado, sensible, secreto

Estado de la API y número de notas indexadas
// Response 200
{
  "status": "ok",
  "vault_connected": true,
  "indexed_notes": 142
}
GET/vault/stats
Totales por tipo, área, notas IA-indexables y pendientes de revisión
// Response 200
{
  "total_notes": 142,
  "by_type": { "proyecto": 18, "accion": 34, "nota": 45 },
  "by_area": { "Laboral": 80, "Personal": 40 },
  "ai_indexable_notes": 98,
  "notes_to_review": 12
}
GET/vault/activity
Últimas notas añadidas, procesadas por IA y pendientes de revisión (máx 6 c/u)
// Response 200
{
  "recently_added":  [...],   // últimas 6 por fecha de modificación
  "processed_by_ai": [...],   // notas con origen: inbox_ia
  "pending_review":  [...]    // revisado: false, estado activo
}
GET/notes
Lista paginada con filtros por cualquier campo del frontmatter
// Query params opcionales:
// area, tipo, estado, sensibilidad, cliente
// organizacion, persona, proyecto, marca, tag
// revisado (bool), prioridad
// page (default 1), per_page (default 20, máx 100)

// Response 200
{
  "total": 45, "page": 1, "per_page": 20,
  "results": [{ "id": "...", "title": "...", "excerpt": "..." }]
}
GET/notes/{note_id}
Nota completa con wikilinks resueltos. Contenido completo solo en scope personal.
// Response 200
{
  "id": "05-proyectos-laboral-acme",
  "title": "Proyecto Acme",
  "metadata": { "tipo": "proyecto", "estado": "activo", ... },
  "content": "# Proyecto...",   // null si scope != personal
  "excerpt": "primeros 400 chars...",
  "resolved_links": { "Juan Pérez": "04-entidades-personas-juan" }
}
POST/notes
Crea una nota en la carpeta correcta según tipo. Solo scope personal.
// Body JSON
{
  "title": "Reunión con Acme",      // requerido
  "tipo": "reunion",                // determina la carpeta destino
  "area": "Laboral",
  "estado": "activo",
  "content": "## Agenda\n\n...",
  "tags": ["cliente"], "cliente": "Acme",
  "personas": ["Juan Pérez"],
  "source_draft_id": "..."          // archiva el borrador origen
}

// Response 201
{ "id": "...", "path": "06 Reuniones y Registros/Laboral/..." }
GET/search
Búsqueda fuzzy sobre título + contenido. Score ≥ 0.5. Máx 50 resultados.
// Query params:
// q (requerido, mín 2 chars)
// area, tipo, estado, sensibilidad
// limit (default 20, máx 50)

// Response 200
{
  "query": "reunión acme", "total": 3,
  "results": [{ "title": "...", "excerpt": "...", "score": 0.95 }]
}
POST/ai/context
Notas más relevantes para un query. Solo notas con ia_permiso:allow e ia_indexar:true.
// Body JSON
{
  "query": "proyectos activos cliente Acme Q2",
  "filters": { "area": "Laboral", "tipo": "proyecto" },
  "max_results": 10
}

// Response 200
{
  "query": "...",
  "results": [{ "title": "...", "excerpt": "...", "score": 0.87 }]
}

// Reglas estrictas (hardcodeadas):
// ia_permiso: allow + ia_indexar: true
// sensibilidad fuera de: privado, sensible, secreto
POST/inbox/draft
Deposita borrador en 01 Inbox/Desde IA/. Queda con estado:borrador, ia_indexar:false.
// Body JSON
{
  "title": "Nota sobre reunión",    // requerido
  "content": "Revisar contrato...",
  "area": "Laboral",                // default: Personal
  "tipo": "nota",
  "cliente": "Acme",
  "proyecto": "Proyecto Q2",
  "tags": ["urgente"]
}

// Response 201
{
  "id": "01-inbox-desde-ia-2026-06-01-nota...",
  "filename": "2026-06-01-nota-sobre-reunion.md"
}
GET/projects/active
Proyectos activos/en_proceso/en_revision ordenados por prioridad.
// Query: area, cliente, prioridad
// Response: array de NoteSummary
// Orden: alta → media → baja → sin prioridad
GET/actions/pending
Acciones pendientes ordenadas por prioridad y luego por fecha ascendente.
// Query: area, proyecto, prioridad
// Estados: pendiente | para_revisar | en_proceso | inbox
// Response: array de NoteSummary
GET/decisions
Decisiones ordenadas por fecha descendente (más recientes primero).
// Query: area, proyecto
// Query: fecha_desde (YYYY-MM-DD) — excluye anteriores a esa fecha
// Response: array de NoteSummary
GET/people
Personas del vault (tipo: persona). Filtros por área, organización, cliente.
// Query: area, organizacion, cliente
// Response: array de NoteSummary
GET/clients
Clientes con conteo de proyectos y personas vinculadas.
// Response 200
[{
  "id": "04-entidades-clientes-acme",
  "title": "Acme",
  "status": "activo",
  "projects_count": 3,
  "people_count": 5
}]

Setup

En cuatro pasos.

Desde cero hasta primera request en menos de 5 minutos.

1

Clonar e instalar

Python 3.11+, virtual env, dependencias.

2

Configurar .env

Ruta al vault y API keys con sus scopes.

3

Arrancar el servidor

Uvicorn con hot-reload o Docker Compose.

4

Primera request

Health check y primer listado de notas.

bash — instalación
git clone <repo> pachimind-api cd pachimind-api python -m venv .venv source .venv/bin/activate # Windows: .venv\Scripts\activate pip install -r requirements.txt
bash — .env
cp .env.example .env # Editá .env: VAULT_PATH=/ruta/absoluta/a/tu/vault API_KEYS={"mi-clave": "personal", "clave-ia": "ai_context", "publica": "public"} LOG_LEVEL=INFO CORS_ORIGINS=["http://localhost:3000"]
bash — arrancar
# Desarrollo con hot-reload uvicorn app.main:app --reload # Producción uvicorn app.main:app --host 0.0.0.0 --port 8000 # Docker docker compose up # Docs interactivas → http://localhost:8000/docs
bash — primera request
# Health check (sin auth) curl http://localhost:8000/health # → {"status":"ok","vault_connected":true,"indexed_notes":142} # Listar notas curl http://localhost:8000/notes \ -H "X-API-Key: mi-clave" # Búsqueda curl "http://localhost:8000/search?q=acme" \ -H "X-API-Key: mi-clave"
